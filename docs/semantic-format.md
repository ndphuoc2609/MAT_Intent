# Luna semantic format

Luna returns a semantic object, not a customer-facing reply. The provider is
asked for versioned strict JSON Schema output generated by
`semantic_model_json_schema(version)`; see `config/schema_versions/` for the
application contracts. The sandbox currently requests v1; the independent
intent API requests v2 and adds `intent_labels`, `category` and `tags`.

After strict-schema null placeholders are removed, a v1 result can look like:

```json
{
  "schema_version": "1",
  "sentiment": "NEU",
  "sarcasm": "absent",
  "scope": "in_scope",
  "requests": [{"topic": "dealer", "desired_outcome": "dealer_lookup", "polarity": "positive"}],
  "operations": [{
    "op": "START_REQUEST",
    "topic": "dealer",
    "request_ref": "topic:dealer",
    "evidence_excerpt": "Đại lý ở Sài Gòn ở đâu?",
    "slot": {"kind": "location", "value": "TP.HCM", "explicit": true, "evidence_excerpt": "Sài Gòn"}
  }],
  "uncertainties": []
}
```

This is the normalized application form, not a literal example of every
nullable placeholder required in the provider's strict schema. The server
binds source IDs and state provenance from its verified snapshot. The app
validates types, evidence, actor/scope and policy before any state change or
reply. Multiple requests and operations remain supported.

JSON Schema constrains the shape but cannot guarantee that the model finishes
within its output budget or that a value is supported by evidence. Missing,
truncated, refused and malformed responses have distinct error codes. In the
local sandbox only, a response explicitly ending with `finish_reason=length`
gets at most one additional model invocation with up to 1,800 output tokens.
Each invocation may itself retry transient HTTP failures according to the
adapter's limit; every HTTP attempt is checked against the configured sandbox
budget mode and recorded in the ledger. Recovery may take longer and cost more. Other failures do not
silently produce a semantic or commit guessed state.
